# 共享响应反演：有界延拓验证与研究裁定

2026-09-28。执行上一轮 PLAN.md（本次未公开） 的 A 阶段。未使用本地 skills；未修改 backbone 或原生部署算子。

## 结论先行

**A 阶段完成。保留主任务，停止把 CSI 分拆、同一支持子空间投影或泛化的零空间敏感性当作主机制。当前证据不足以自动启动 B 阶段主动采集，也未形成可晋升主论文的新算法。**

主任务仍是：已完成的视觉作用经历，如何修订同一个预测器，使未执行动作链的完整后果、相对后果与选择得到改善？这轮没有改换主问题。

本轮真正收紧的地方有两项：

1. 当前普通适配几乎已经满足支持子空间限制；再施加同一个限制基本不改变预测。
2. L1 的当前修正在八条候选的首步上都沿着增加视觉误差的方向。对这条固定修正射线，仅缩小正幅度不能优于未在线适配的 PRIOR。

同时，确实存在保持支持预测、改变查询后果的有限预算规律。但这些是敏感性见证，**不是用于找出正确规律的估计器**。其存在未证明真实物理规律属于这个集合；其未改善某项指标也不能用来否定辨识或后验方法。

据此，结束这轮局部审查。下一项值得投入的工作应形成一个有依据、可计算的跨动作响应关系；只有它能说明经历为何约束另一条动作的作用过程，才进入算法和辨识实验。继续增加扰动方向、投影层或概率包装，尚无研究依据。

## 2. 同一支持子空间投影基本是恒等操作

令 Δ=Θ_DIRECT−Θ_PRIOR，V 是 DIRECT **自身支持路径**上的两列特征，P 投影到 col(V)。按此前推导，Θ̄=Θ_PRIOR+ΔP 保持支持路径，理想精度下减少 λ‖Δ(I−P)‖² 的正则项。它不是用查询真值选出的投影。

| 案例 | ‖Δ(I−P)‖/‖Δ‖ | 投影后支持最大逐值变化 | H5 查询最大逐值变化 |
| --- | ---: | ---: | ---: |
| T0 | 1.1642e-5 | 2.3842e-7 | 1.4305e-6 |
| T1 | 1.2660e-5 | 4.7684e-7 | 1.4305e-6 |
| L0 | 5.8560e-6 | 4.7684e-7 | 1.4305e-6 |
| L1 | 5.7781e-5 | 4.7684e-7 | 5.2452e-6 |

四案 V 均为秩 2。全部变化小于继承的 2e-5 逐值容差，没有放宽门槛。结果意味着：在**当前特征、先验和正则**下，新增相同的子空间限制没有形成实质干预。它不排除新特征、不同先验度量或新信息产生不同延拓规则。

首步修正的共同成分占能量约 90.94%、97.56%、99.43%、94.79%。成功案和失败案都以共同变化为主，因此不能据此发明“扣除共同偏移”。特征四块的作用、支持 Gram 系数和正交残差保存在 TRACES.pt（本次未公开） 与 [DIAGNOSTICS.json](DIAGNOSTICS.json)；各块 RMS 不能直接相加。

## 3. L1 首步失败涉及方向，不能仅靠同向缩小恢复

在固定查询初态和首个动作下，预测关于响应参数为仿射函数。令 e 为 PRIOR 首步预测减真值，d 为 DIRECT 首步预测减 PRIOR，则固定射线 Θ(α)=Θ_PRIOR+αΔ 满足

\[
\mathrm{MSE}(\alpha)-\mathrm{MSE}(0)
=2\alpha\langle e,d\rangle+\alpha^2\langle d,d\rangle,
\]

内积按全部候选和 visual 坐标取均值。L1 的实际分解为

\[
\mathrm{MSE}(\alpha)-\mathrm{MSE}(0)
=0.02477774656\alpha+0.00439450049\alpha^2.
\]

八条候选各自的交叉项也全为正。因此，对任意 α>0，当前方向的首步 MSE 都比 PRIOR 大。实际 α=1 时，首步 MSE 从 0.07361370 增至 0.10278595。

这是评估后进行的方向诊断，**没有用真值选择 α 或部署负方向修正**。它严格限定于当前参数射线、首步及视觉 MSE；重新选择正则并重新拟合可能改变方向，本轮没有证明那种方法无效，也未证明具体物理根因。

失败并不统一：T1 的交叉项为负但修正能量较大，呈现当前方向上的过冲；T0、L0 的当前方向在首步有收益。不能拿 L1 的分解为所有案例建立同一个解释。

原计划要求区分直接更新和自产历史传播，也已由记录轨迹补齐，未新增模型调用：L1 首步传播项 RMS 约 4.49e-8，第五步为 0.097798；第五步同状态直接更新 RMS 为 0.017750。该分解是代数恒等式，传播项包括基座和 PRIOR 对变化历史的响应，不是另一个被识别的物理机制。支持自产末端缓存也不等于查询的真实历史，L1 三帧 visual MSE 为 0.0039794。因此不能将所有差异统称为纯动作外推。详见 [PATH_DIAGNOSTICS.json](PATH_DIAGNOSTICS.json)。

## 4. 等支持规律会产生分歧，但尚未形成纠错规则

关于 Θ̄ 构造 Θ±=Θ̄±ρuvᵀ，其中 v 与支持空间正交，u 来自合法离线残差，ρ²=ηJ(Θ̄)/λ。每套规律跨所有候选和完整路径共享，不逐候选挑物性。

检查结果：支持最大变化 9.54e-7；实际与解析目标增量之差最大 1.32e-6；首步正负平均与中心预测最大差 2.38e-7。由此核对了支持保持、预算和首步仿射性质。

主预算 η=0.1 下，正负规律产生以下后果分歧。数值为完整 visual 坐标的 RMS；候选中心化分歧衡量相对后果，不是与真值的误差。

| 案例 / 方向 | 首步总分歧 RMS | 首步候选中心化分歧 RMS | 第五步总分歧 RMS |
| --- | ---: | ---: | ---: |
| T0 / COMMON | 0.031932 | 0.013337 | 0.017236 |
| T0 / DIFFERENTIAL | 0.030747 | 0.014139 | 0.011903 |
| L1 / COMMON | 0.028353 | 0.009975 | 0.038815 |
| L1 / DIFFERENTIAL | 0.021951 | 0.016506 | 0.012758 |

首步闭式最大界和全部半径记录在 [AUDIT.json](AUDIT.json)。这些预算属于指定正则目标的敏感性尺度，不是校准过的后验概率或物理可信区间。多步只检查一个离线输出方向和两个输入方向，不能代表全部相容规律。

## 5. 研究层次与下一步边界

用户要求的强度始终是：重要模型的一项核心用途出现可复现困难；应用数学重建改变实际求解对象；完整算法解决这项困难，并面对同信息的强常规方法。当前四案属于机制形成证据，尚不满足论文层面的普遍性或新颖性。

本轮不把“有限数据不能确定所有参数”命名为 JEPA 特有结构缺陷，也不把标准投影或不确定性估计升格为贡献。CSI 的求解方式没有证明额外价值；现有响应模型仍保留作基线和对照，没有被证明整体不可用。

从现有模型可以清楚写出剩余问题。由于 Δ≈ΔP，首步修正近似为

\[
\Delta\phi_q\approx (\Delta V)(V^\top V)^{-1}V^\top\phi_q.
\]

这说明在当前模型中，支持路径上的修正通过缓存与动作特征的 Gram 关系延拓到查询。该关系本身是标准线性代数，不是新机制；L1 的方向错误也尚未单独证明“内积”就是根因。

**下一步的具体问题是：合法视觉经历与原生模型查询，能提供什么关于作用过程的对应关系，使一段经历支持的响应约束在新动作中以正确的方向、时机和强度生效？** 若需要重新定义未知量，应明确它是共享动力学参数、作用过程上的响应算子还是其他对象，并写出从可获得信息到它的计算过程；不能只写一个“真实规律”变量来代替这一步。

下一次机制形成只接受一份可判定的完整提案：

1. 写出一条跨动作关系及其成立条件，说明它使用哪些已观测量与原生模型查询，不能借入未执行动作真值。
2. 给出求解对象、约束与可执行更新，并解释普通同信息回归/辨识为什么没有自动实现这条关系。已有数学可以用，贡献必须来自实际新增能力。
3. 提前给出它与普通适配不同的预测，以及一个决定去留的最小对照。只有这个关系需要某种尚缺的辨识观测时，才设计 B；不能仅按当前模型的任意分歧采集数据。

这些是下一次投入的进入条件，不是本轮已经形成的新算法。若找不到这样的关系，当前“共享响应反演”实现继续作为研究记录和基线，不靠扩场景或增模型包装为主论文。当前主任务保持不变。

## 6. 验证范围、风险与复现

- 原始 DIRECT 查询逐值复现；旧 NATIVE/PRIOR/STEP_RIDGE/DIRECT 的核心评分与上一轮差值低于 1e-12。所有新预测锚点、存储代价重放均通过既定 2e-5 检查。
- 旧真值代价重放仍有 4/32 项未过 2e-5，上一轮记录最大差约 6.12e-5。保留该限制；没有改评分或放宽门槛。regret 使用旧记录代价，不宣称本轮修复了这项问题。
- 后验均值首步限制、投影和正负预算经过代码及独立数学复核。独立复核见 [INDEPENDENT_REVIEW.md](INDEPENDENT_REVIEW.md)。
- 本轮没有校准新的在线 λ，没有新增数据，也没有覆盖新的模型或独立任务。不能从四案推广为所有视觉世界模型的普遍结论。
- 新代码不修改主算子路径。复现程序默认拒绝覆盖已有实验产物；需要重新执行时，应先在独立输出目录放置代码和协议，保留当前封存结果。
