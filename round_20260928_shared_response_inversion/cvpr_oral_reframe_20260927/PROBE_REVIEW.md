# Independent native-probe review

Reviewer: `/root/probe_review`; 2026-09-27. The initial phase was static review only: I did not execute the model, inspect forecast metrics, or edit the runner/protocol. A subsequent phase inspected sealed forecast metrics and independently recomputed statistics, as documented in the final adjudication below. ## Verdict

No blocking time-index, target-alignment, or observation-leakage error was found in the reviewed three-arm design. The completed FP32 execution and independently recomputed statistics pass the scoped review; see the final adjudication below. The initial review preceded scoring, and its pending aggregation check has now been resolved.

The initial cache-invariant failure must remain part of the execution record. The reported same-frame batch-encoding discrepancy does not establish a scientific observation-update effect. Uniformly disabling TF32, retaining the frozen `atol=rtol=1e-5` cache check, and rerunning before any scoring is an acceptable numerical execution correction. It is not a new scientific arm or a threshold relaxation. This review does not independently establish TF32 as the sole root cause; the subsequent invariant checks must establish whether the corrected execution meets its contract.

## Time and action indices

Write actual endpoint observations as `x_0,...,x_n`, and packed actions as `a_0,...,a_(n-1)`, where `a_i` connects `x_i` to `x_(i+1)` over five environment steps. `_load_segments(..., count=k)` reads segments `0,...,k-1`; concatenating the first start with all endpoints correctly yields `x_0,...,x_k`. The loader and explicit adjacent-endpoint checks validate this convention.

At cut `k`, IMAGINE starts from real observations ending at `x_(k-1)` and uses `a_(k-1)` to produce its predicted current token. Its second predictor call is therefore the first common forecast call for `x_(k+1)`. FULL starts with the actual window ending at `x_k`; its first predictor call forecasts that same `x_(k+1)`. The capture indices `before+1` and `before` are correct. From that call onward the old observation tokens and packed-action slots should agree, with the current observation token being the intended intervention. The runtime cache checks are necessary to validate this argument numerically.

Native `rollout` returns observations from its initial index `first` through `n` inclusive. The slice `cut+1-first:` therefore returns `x_(k+1),...,x_n`; the scoring target `truths[cut+h]` is aligned. The expected call count is `n-k+1` for IMAGINE and `n-k` for each other arm, consistent with the protocol's aggregate `3*229+93=780`.

## Information separation

Prediction loads every recorded action chunk, but accesses observation contents only through the current prefix. Future observation contents are used by the separate score phase after `SEALED.json` and prediction hashing. Reading file bytes for hashing is not a model-input information channel. Prefix observations and actions are not passed to any training routine; frozen parameter/buffer version checks are present.

The action sequence itself was generated by an actual closed-loop policy and can depend on later observations. Conditioning all arms on that same retrospective action sequence is legitimate for this diagnostic, but does not establish prospective online forecast quality or a deployable control policy. No counterfactual action consequence, candidate ranking, regret, or planning success follows from these metrics.

The source path uses the already existing native `rollout` with all optional transition/revision callbacks left `None`; there is no second learned operator or a hidden correction branch in this experiment.

## Encoder and numerical checks

`SmallResNetGeM` encodes flattened frames independently. `ProprioceptiveEmbedding` uses a Conv1d with the configured kernel and stride both equal to one, followed by per-step LayerNorm. It does not add temporal position embeddings. The configured image preprocessing is deterministic resize, center crop, and normalization. There is therefore no intended semantic dependence of an observed frame's encoding on the number of other time steps encoded in its batch.

Native `ViTPredictor` does add learned positional embeddings. This is relevant to interpreting SINGLE versus FULL, as detailed below, but does not explain a discrepancy in the captured pre-predictor encoding of the same old frame.

The original exact `torch.equal` assertion for separately encoded action tokens was stronger than the frozen protocol's stated numerical tolerance. Replacing it with that same frozen `allclose` test is acceptable when raw action identity and indexing remain fixed. Raw actions already originate from a single shared tensor with aligned slices; there is no action optimization in an arm.

## Required interpretation limits

1. IMAGINE is a **one-step imagined-current prior at each cut**. It restarts from up to three preceding actual frames. It is not an uninterrupted episode-long open-loop imagination stream.
2. FULL is the complete **native window of at most three observations**, not unlimited history and not a trained recurrent/filtering baseline. For `k=1`, only two actual observations exist and FULL correctly uses two.
3. SINGLE versus FULL changes historical evidence, input length, and the learned positional index assigned to the latest token. It identifies an effect of the native re-entry/context configuration; it cannot by itself attribute the effect purely to missing semantic history. A result favoring FULL should not be called a new memory mechanism.
4. FULL versus IMAGINE has the cleaner first shared call: equal length, positions, retained old tokens and action slots, with the current observation token changed. Even there, current evidence changes both visual and proprioceptive components. It is not a visual-only intervention.
5. A three-frame restart that fails would still admit training-distribution, representation, positional, and model-misspecification explanations. It would not prove a universal failure of conditioning or JEPA prediction.
6. The donor metadata identifies two shape-specific runs with seed 101. This is not a multiple-training-seed or multiple-donor-seed robustness study. Existing development data also does not establish held-out generalization.

## Statistics to verify after scoring

The protocol's trajectory-first averaging avoids treating correlated cut/horizon values as independent samples. Paired differences must be formed at trajectory level. Resampling must preserve pairing of arms and the fixed T/L counts. Per-shape and per-horizon results should accompany the overall aggregate so their disagreement remains visible.

The combined score is a sum of two separately averaged latent MSEs. It is a diagnostic convention, not physical error, probability calibration, or task utility. Both component metrics must remain visible even when the sum favors an arm. Bootstrap intervals are conditional on this small existing trajectory pool and checkpoint; they are not model-seed uncertainty. Since both shape runs share the seed number, any cross-shape dependence should not be assumed absent when making broader inferential claims.

At the initial review, the reviewed runner did not implement aggregation/bootstrap, so statistical verification remained pending. The subsequent review of `summarize_probe.py` and independent recomputation closed that item; see the final adjudication below. The current input manifest hashes the checkpoint, observations, runner, protocol, main rollout, predictor and loader; it does not hash every transitive dependency/configuration. A claim of complete environment reproducibility would therefore be broader than the current manifest supports.

## Final adjudication after sealed FP32 scoring

The follow-up review inspected `summarize_probe.py` and the `native_probe/fp32/` manifest, seal, cache checks, metrics, and summary. I independently recomputed the descriptive means and confidence intervals from `METRICS.csv`, without running inference or modifying results. The independent calculation used grouped trajectory values and `math.fsum` rather than executing the submitted summary script.

**Verification passed.** The 687 rows contain exactly the expected unique `(shape, sample, cut, horizon, arm)` combinations: 24 trajectories, 93 cuts, 229 cut/horizon pairs and three arms. No missing, duplicate, nonfinite, or negative metric cells were found. Each combined metric equals the two component metrics' sum. Trajectory-first overall and shape means, all horizon means/counts, comparison means, win counts and bootstrap interval endpoints agree with `SUMMARY.json` to absolute error below `1e-15`. The prediction file SHA256 matches `SEALED.json`.

The summary resamples twelve trajectory indices independently within T and twelve within L, with replacement, 10,000 times and seed 260927. Each draw applies the same trajectory indices to paired arm differences. It therefore implements the frozen shape-stratified paired bootstrap and does not treat overlapping cut/horizon errors as independent observations. Horizon summaries use 24, 24, 23 and 22 available trajectories for horizons 1 through 4; these are changing available cohorts, so their sequence is descriptive rather than a controlled same-cohort horizon comparison.

The seal reports 780 predictor calls, no training/environment calls and no parameter/buffer or protected-input mutation. All 93 cache checks were saved. Maximum retained-token absolute discrepancy is `2.86102294921875e-6`, below the unchanged `1e-5` absolute tolerance; captured action-token discrepancy is zero. This closes the initial execution-invariant failure for the uniform FP32 run. It does not erase the failed initial execution or establish a universal numerical explanation beyond the checked run.

Both real-observation arms have lower trajectory-averaged visual error than IMAGINE on all 24 trajectories. This is **not** a statement that every individual cut/horizon improves. Proprio improves on 23/24 trajectories for FULL and 21/24 for SINGLE; the sum improves on 24/24 for each.

`SINGLE - FULL` visual difference is `-0.0004926991`, with interval `[-0.0010911873, 0.0002237139]`; 17 trajectories favor SINGLE and 7 favor FULL. The proprio and sum intervals also cross zero. No reliable overall superiority of either real-observation arm is established here, and crossing zero does not establish equivalence. Shape means also differ in their ordering: T very slightly favors FULL for visual error, whereas L favors SINGLE.

**Permitted conclusion:** on this checkpoint and existing fixed-action development trajectory pool, incorporating the current actual visual/proprio observation improves the measured future latent forecasts relative to the specified one-step imagined-current prior. The proposed native diagnostic does not reproduce a broadly harmful observation update.

**Not supported:** that single-frame re-entry is the limiting bottleneck, that retaining three frames is necessary for improvement, that a pure visual update caused the improvement, that unlimited history/filtering has been tested, or that any new mechanism or action-selection benefit has been established. In particular, both FULL and SINGLE improve, so the result cannot be presented as confirmation of the original context-bottleneck prediction. This negative outcome for that motivating hypothesis is usable evidence for the re-approval decision, within the stated scope.
